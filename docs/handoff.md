## 5. 不要误读的已确认业务规则

### 5.1 身份、字段与展示

任何注册用户均可发起和报名，只管理自己发起的活动。身份按活动而定，没有独立平台管理员。匿名可看已发布列表/详情，不能看私密申请、完整名单、理由或通知。发起者可手动报名自己的活动，按相同规则占正常名额；发布不自动报名，审核模式不自动通过，本人申请也执行审核。

按已批准的 Story 2.4/2.8，本人也是发起者时可按本活动管理权限处理自己的参加/退出请求，但仍受状态、版本、时间和容量约束；不额外引入“必须另一管理员审核”的新角色。

| 输入 | 已确认约定 |
|---|---|
| 用户名 | trim 后 3–32 个 ASCII 英文字母/数字/下划线，小写标准化并唯一 |
| 昵称 | trim 后 1–32 个 Unicode 码点，支持中文、不要求唯一 |
| 密码 | 不全为空白，至少 8 个 Unicode 码点、UTF-8 至多 72 字节；不 trim、不改变、不静默截断 |
| 活动标题/说明/地点 | 纯文本，分别至多 100/5000/200 个 Unicode 码点 |
| 容量 | 已填为正整数；没有确认另加业务人数上限 |
| 活动时间 | 报名开始＜截止≤活动开始；结束可选，填入时晚于开始 |
| 参加拒绝理由 | 选填，trim 后至多 500 个 Unicode 码点，空白视为未提供 |
| 退出申请理由 | 必填纯文本，trim 后 1–500 个 Unicode 码点；与上一个字段不同 |

草稿可全部未填，但已填字段/相关时间关系须合法；模式和退出策略不偷偷补默认值。草稿暂填过去时间不构成已开始或报名永久关闭。发布必填标题、说明、地点、容量、报名起止、活动开始、模式和退出策略；结束可选。发布时截止须在实际校验时点之后，报名开始可已经到达。

成功名单仅向发起者展示用户名、昵称和报名状态，申请记录另有原提交时间；退出理由放私人请求视图，不塞入名单。发起者的申请/名单按原申请时间升序、同刻受理序号升序；本人历史最近在前。两者显示顺序用途不同，审核模式没有强制按序通过的规则。

公开列表保留已截止/已开始/已结束活动，未取消组默认发布时间倒序、同刻 ID 数值倒序；有结束且已到才显示已结束，未填结束不猜时长。取消活动必须排在全部未取消活动之后，标“活动已取消”；取消组内细则在对应故事明确，不擅自扩大批准范围。初版公开列表及本人历史没有新增搜索/筛选/分页；若以后分页，先全局排序再分页。

### 5.2 名额、报名与时间

只有参加尝试 `CONFIRMED` 占位。参加 `PENDING` 和 `WAITLISTED` 不占位；退出请求 `PENDING` 对应参加仍 `CONFIRMED`，所以仍占位。始终保持 `已占 = CONFIRMED 人数`、`剩余 = 容量 − 已占 ≥ 0`。

新申请只能在 `open ≤ now < close`，已截止不因改期重开。先到先得有可分配名额才成功，普通满额失败者**不会自动变候补**。审核模式满额仍接收 PENDING，有空位也不自动通过；发起者可在开始前手动通过任一有效待审，受容量约束。截止前受理的旧申请可在截止后审核，活动开始时停止。

活动开始前，尚未入名单的待审/候补可本人直接撤回，包括报名截止后；若审核/补录先录入成功，就须按成功者退出策略处理。开始边界不是报名截止边界，不能混成一个按钮禁用条件。

### 5.3 退出、重报与历史

成功者在开始前按独立退出策略处理：FREE 直接退出；受限则提交理由经发起者审核。真实退出才释放一次；请求提交、退出拒绝、撤回退出请求都不释放。两种报名模式与两种退出策略的四种组合均成立。

开始前可撤回待审退出请求，被拒后可重新申请退出；每次新请求使用新 ID，保留旧历史。退出请求终态不等于参加终态：退出被拒/撤回后仍成功者不能重新报名。

参加被拒、撤回或已真正退出后，报名仍开放才可重报：新 attempt、新受理时间/序号，不复用旧排名或恢复旧终态。`expectedPreviousAttemptId` 用来核对用户看到的最近允许终态，防止旧页面误创建更多轮；首次空/缺省只在没有既往尝试时允许新执行。旧审核、撤回、退出及旧回执不能改新一轮，当前资格单独显示。

### 5.4 模式切换、公平队列、变更与取消

审核→先到先得：已有成功者不变，有效旧 PENDING 按 `(原提交时间, 活动内受理序号)` 先录入，剩余为有序 WAITLISTED；新报名不能插队。切回审核：成功者不变，剩余候补变 PENDING、保留原键，停止自动通过。退出/退出获批/扩容产生空位时，当前先到先得且未开始/未取消才同步按序补录；截止后只能补旧候补，不能新增申请。失效历史不复活。

开始前可改业务设置；开始后仅普通信息（标题/说明/地点）和公告可改，不能改时间、容量、模式、退出策略，也不能整场取消。所有已发布变更/公告更新/取消须说明，按变更前成功名单产生站内通知，含退出待审者，不含仅参加待审/候补者；同变更同收件人只一条，不能变更成功却漏通知。

整场取消只能开始前：保留活动/原因/历史，关闭待审参加、候补和待审退出请求，停止报名/审核/个人撤回退出/补录；原成功记录不能伪装为主动退出。列表全局沉底，通知仍可读和标记已读。活动取消不能靠删除记录实现。

已明确不做支付、短信、小程序、独立平台管理员；只采用站内通知。其他裁剪仍按 A-8 复核，不把候补和退出审核重新删出第一版。

## 6. 架构与实现时必须共同遵守的约定

这是设计及已审阅故事的摘要，不是已存在的 Java 类、SQL 表或部署。整体架构仍 draft；具体实现先读正式故事和 ADR，不把技术建议整体标为已批准，也不无记录改成另一套方案。

| 主题 | 约定及原因 |
|---|---|
| 单体/模块 | Vue → `/api` → Spring MVC JSON；identity/activity/participation/notification 模块，应用层协调，后端裁决资格 |
| 活动事务 | 已存在活动的全部业务写先锁活动根行 `FOR UPDATE`，同一 Spring JDBC READ_COMMITTED 事务读/改；不用独立提交或持锁调外部服务 |
| 人数真值 | 从 CONFIRMED 计数，不维护第二份可写已占人数；容量/汇总/名单读取同一一致快照 |
| 时间 | 锁后用另一个 SQL 取 `UTC_TIMESTAMP(6)`，分配资格/最终写前复核适用边界；跨边界整条回滚，不能使用等锁前旧时间 |
| 当前与历史 | `(activity_id,user_id)` 唯一 slot 指当前 attempt；拒绝/撤回/退出清指针，重报新建 attempt；exit_requests 独立，至多一个有效待审指针 |
| 状态/版本 | attempt 与 exit request 版本不能混用；配置版本不因每次报名递增；旧 ID/版本/指针冲突拒绝，不能按 userId 处理任意轮次 |
| 幂等 | 活动命令带 Idempotency-Key，回执 `(actor_id,key)` 唯一且同事务；身份/目标权限检查后，成功回执先于新状态/时间门槛重放，重放后查当前状态 |
| 跨活动同键 | 唯一冲突要回滚整个命令后核对原回执，不能一边提交业务一边返回冲突 |
| 会话 | Spring Security 服务端 HttpSession；Cookie HttpOnly/SameSite=Lax，HTTPS 下 Secure；登录轮换、退出失效，密码 BCrypt |
| CSRF | 写操作全部保护，注册/登录也包括；先 GET `/api/auth/csrf`，写带 X-CSRF-TOKEN；登录/退出后重新取令牌；不改用 localStorage JWT |
| 登录格式 | POST `/api/auth/login` 表单编码 username/password，响应 JSON；其他业务写用 JSON，退出登录为 POST |
| 接口 | camelCase JSON、BIGINT ID/序号用十进制字符串、UTC ISO 时间带 Z；前端北京时间显示，不能按字符串重排序号 |
| HTTP | 400 参数、401 未登录、403 无权、404 不存在/不可见、409 状态/容量/时限冲突、503 可重试基础设施失败；私人响应 no-store |
| 通知 | 原名单快照、不可变变更、业务和通知同事务，每变更每收件人唯一；不能改成成功后再异步补写而漏通知 |
| 数据库 | Flyway 唯一迁移入口，已共享迁移不改写，只在故事需要时建/扩表；正常重启不清数据，测试使用独立真实 MySQL，不以 H2/Mock 替代一致性验收 |
| 交付 | 开发 Vite 代理，交付 Vue 构建物由 Boot 同源提供，API 404 不被 SPA 回退吞掉；单实例，无 Redis/消息队列前提 |
| 秘密 | 凭据从环境传入，只提交无真实秘密的示例；日志不含密码/编码、会话、退出理由 |

设计枚举在 SPINE 的 AD-3：活动 DRAFT/PUBLISHED/CANCELLED；参加 PENDING/WAITLISTED/CONFIRMED/REJECTED/WITHDRAWN/EXITED/CLOSED_ACTIVITY_CANCELLED；退出请求另有 APPROVED 和关闭终态，不能共用“审核状态”误改另一对象。时间阶段是派生展示，不凭空新增“已开始”等持久化枚举。

未来候补及关闭终态虽已有设计，仍须按真实需要增量实现，不能在第一条注册故事先建全部业务表。先到先得释放与旧请求关闭的跨阶段规则须随相应 Epic 3 入口一起落地。
