### Story 1.5: 公开浏览已发布活动列表与详情

As a 想了解班级或社团活动的同学，
I want 无需登录即可查看已发布活动列表，打开详情了解时间、名额及参与条件，
So that 可以判断哪些活动值得进一步参加。

本文件保留已审阅快照。用户于 2026-11-27 回复“通过”，确认 Story 1.5（D-021）；正式维护入口为 epics.md，本文件不再独立演进。实施前置为 Story 1.1–1.4。规范扩展最小公开详情并建立发现列表，不依赖未来报名写接口；取消的创建、原因/历史和沉底仍由 Epic 3 连同取消流程接入，规则未删除。获批不表示已实现或测试，也不声称已完整交付 FR-05 的取消场景。

**Acceptance Criteria:**

#### AC-1.5-01 未登录也能发现已发布活动

**Given** 存在已发布活动、本人/他人的草稿，以及尚未登录的访问者，
**When** 打开活动列表，
**Then** 列表可正常读取而不跳到登录页，只返回当前已交付范围内的 PUBLISHED 活动，DRAFT 永不出现在公开列表，
**And** 每项显示标题、发起者展示名、地点、时间、模式、容量与名额信息，并可打开已有公开详情，
**And** 默认按发布时间从新到旧，相同发布时间按数据库活动 ID 数值稳定倒序，由服务端统一排序，前端不按字符串重新排序；已截止或已开始的活动不被默认隐藏，
**And** 本故事不新增搜索、筛选或分页；若以后采用分页，必须保持完整结果排序后再分页的已确认规则。

#### AC-1.5-02 详情完整表达参与条件

**Given** 活动已发布，或请求的 ID 仍为草稿/不存在，
**When** 匿名或已登录用户打开详情，
**Then** 已发布记录返回 HTTP 200，展示标题、纯文本说明、地点、发起者展示名、报名起止、活动开始、可选结束、当前模式和独立退出策略，
**And** 未填结束时间明确表示未设置，不猜测结束时刻；四种模式/退出组合均按实际值显示，
**And** 草稿或不存在记录均为 404，不回退到私有草稿，也不泄露其标题或拥有者。

#### AC-1.5-03 剩余名额取真实成功记录

**Given** 数据库中存在已发布活动及有效测试数据，包括 CONFIRMED、PENDING、WAITLISTED、REJECTED、WITHDRAWN、EXITED 等记录，
**When** 读取列表或详情，
**Then** 已占名额等于该活动 CONFIRMED 数量，剩余名额等于容量减该数量；待审、候补及非成功历史不减位，
**And** 容量与人数来自同一数据库快照，不能拼接两个时点或用前端自行计数；没有记录时由真实查询得到 0，不硬编码演示人数，
**And** 为这个只读计数建立当前确实需要的最小报名记录及归属结构；后续写故事复用并增量扩展，不要求先实现提交/审核/退出，
**And** 退出待审仍属于 CONFIRMED 的既定语义不变；真实退出申请与计数的联动在对应退出故事验证，不把本次夹具读查询测试说成退出流程已经运行。

#### AC-1.5-04 时间状态取服务端时点

**Given** 时间有效的已发布活动，服务端返回本次读取采用的时间依据，
**When** 读取或刷新列表/详情，
**Then** 按下表显示当前阶段，不以访问者电脑时间判断资格，
**And** 恰好到报名开始时进入报名中，恰好到截止时不再显示仍在接收新申请，恰好到活动开始时显示已开始；截止等于开始时不制造不存在的中间窗口，
**And** 若已有持久化的报名关闭事实且未开始，仍显示报名已截止，即使后来改期后的日期尚在未来；本故事只读取，不修改关闭事实，
**And** 页面按北京时间展示接口中的 UTC 时点，不能因为浏览器时区不同改变业务阶段。

#### AC-1.5-05 满额提示区分报名模式

**Given** 活动在报名时间窗口内，剩余名额为 0，
**When** 分别查看先到先得与审核模式，
**Then** 先到先得明确显示名额已满，审核模式明确说明“名额已满，仍可提交待审核申请；待审核不代表报名成功”，
**And** 未开始、已截止或已开始等时间限制不因审核模式或剩余名额大于 0 而被忽略，
**And** 本故事仅表达阶段、人数与规则，不新增报名写入口或返回假报名成功；也不替尚未确认的发起者自报名规则给出本人一定可报名的判断。

#### AC-1.5-06 公开读取不扩大私密权限

**Given** 系统已有受保护的身份、私有草稿路由和公开活动路由，
**When** 匿名用户读取公开活动并尝试读取私有草稿/本人身份或调用写接口，
**Then** 只对精确的公开 GET 路径开放访问，不将整段 `/api` 或活动写接口开放，
**And** 公开响应不含完整名单、退出理由、私密申请、密码、会话标识或命令回执；当前身份/私有数据仍按前述故事拒绝匿名访问，
**And** 文本按纯文本展示，不执行脚本；无效/不可见 ID 有明确 400/404 JSON 结果，公开正常请求不会返回默认登录 HTML 或 302。

#### AC-1.5-07 空列表、失败和刷新有真实反馈

**Given** 没有已发布活动、接口失败或请求正在加载，
**When** 用户打开列表或详情，
**Then** 分别显示加载、暂无已发布活动、读取失败或不存在的明确状态，不用示例活动伪装真实结果，
**And** 刷新重新读取数据库结果，列表/详情使用 `Cache-Control: no-store`，不把旧缓存人数或时间状态当作最新资格，
**And** Cookie 已过期不阻断匿名可用的公开浏览，当前身份失败不会把整个公开页面强制导向登录，
**And** 读取不创建申请、不占名额、不更新配置版本、通知已读或报名关闭事实。

#### AC-1.5-08 正常重启保留活动与展示依据

**Given** 活动已发布且相关记录已存入真实 MySQL，
**When** 正常重启再读取，
**Then** 活动 ID、字段、发布时间与顺序保持一致，名额按原有记录重新计算，
**And** 时间阶段可随真实时间推进，不能把“阶段变化”误判为数据丢失，也不能为恢复旧显示回写时间，
**And** 草稿仍私有，注册、登录/退出、草稿和发布流程不因新增读取功能失效。

#### AC-1.5-09 独立验证与阶段边界

**Given** 未来的报名、审核、退出、模式变更和取消写流程尚未实施，
**When** 用真实 MySQL 测试夹具核对公开读模型，并以浏览器完成发现/详情路径，
**Then** 保存列表顺序、同刻稳定排序、隐私、计数、时间边界、两种模式满额提示、空/失败状态及重启读取的实际证据，
**And** 只创建当前读模型所需的最小 participation_slots / registration_attempts 字段与约束，以及确需的活动读取字段；不预建退出请求、变更或通知表，
**And** 夹具只用于测试，不提供对外造数据后门或模拟报名界面，不把夹具记录称为真实使用者报名，
**And** 不把读查询验证写成未来写流程、最后名额并发或完整取消流程已完成，当前不直接标记 ready-for-dev。

#### 已确认的阶段显示约定

以下仅定义展示，不改变已确认的报名、审核、退出和补录截止规则。优先按已结束/已开始判断，再判断不可逆关闭事实与报名起止。

| 条件 | 显示 |
|---|---|
| 填写了结束且服务端时间已到结束 | 活动已结束 |
| 已到活动开始、但不满足上项 | 活动已开始 |
| 未开始，已有关闭事实或已到报名截止 | 报名已截止 |
| 未开始、未关闭，未到报名开始 | 报名未开始 |
| 未开始且报名开始≤当前时间＜截止，没有关闭事实 | 报名中；满额另按模式提示 |

未填结束时间时，开始后只显示“已开始”，不自动假设持续时长。本次已确认默认保留已截止/已开始/已结束的已发布活动，不增加按阶段隐藏的规则。

#### 读取、表结构与接口约定

- `GET /api/activities`：本故事的公开列表，空结果为 200 和空列表；默认发布时间倒序、ID 倒序，不做新增筛选或分页。
- `GET /api/activities/{activityId}`：扩展 Story 1.4 的公开详情，补齐真实名额和阶段；不另建第二套公开详情协议。
- 精确字段、时间依据和版本/ID 类型在实施前纳入共同契约，避免前端与后端各自解释“报名中/满额”。
- 名额不能依赖未来尚不存在的表或用常量代替。因此，本故事按 AD-3 建当前查询实际需要的最小 slot/attempt 关系及确认状态；后续报名故事才提供其业务写入口，退出请求等字段随真正需要时迁移增加。基于 SQL 测试夹具验证读逻辑不等于提前实现未来业务。
- Epic 3 开放整场取消时，按已确认规则把 CANCELLED 纳入完整列表并全局沉底，补齐原因/历史详情与通知；当前不生成取消入口，不把本次完成当作 FR-05 取消场景已验收。

D-021 已确认默认新发布在前、保留各时间阶段活动、结束时间的展示推导、真实名额读模型，以及初版不增加搜索/筛选/分页。其他行为承接 PRD；所有 AC 为已批准规范，仍没有运行结果。
