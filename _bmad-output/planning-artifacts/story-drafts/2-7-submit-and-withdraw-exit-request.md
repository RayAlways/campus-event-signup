### Story 2.7: 受限退出时提交理由并撤回待审退出申请

As a 已报名成功但无法参加、且活动要求审核退出的同学，
I want 说明理由申请退出，也能在改变主意时撤回尚未处理的退出申请，
So that 发起者能了解情况，而申请期间我的参加资格和名额不会被提前取消。

本稿待审。D-028 只批准 Story 2.6，不批准本稿。前置为十一条已批准规范；在固定活动设置下提供真实提交、撤回及私人读取，不依赖未来审核按钮才能提交/撤回。退出通过或拒绝由 Story 2.8 实现，策略变更、候补补录和取消仍随 Epic 3 接入。

退出理由必填及仅本人/发起者可见已有需求依据。本稿新增建议：**退出理由使用纯文本，去首尾空白后为 1–500 个 Unicode 码点，空白、超长或类型非法均拒绝。**这不是沿用参加申请的“拒绝理由选填”，也不新增证明材料或附件要求。

**Acceptance Criteria:**

#### AC-2.7-01 成功者提交受限退出申请

**Given** 用户已登录且有有效 CSRF，活动已发布、未开始，当前退出策略为 APPROVAL_REQUIRED，本人当前尝试为 CONFIRMED 且版本匹配，没有待审退出请求，
**When** 提交理由、报名尝试 ID、expectedVersion 及幂等键，
**Then** 返回 HTTP 201、新退出请求字符串 ID、PENDING、版本和服务端提交时间，将其关联到本次报名尝试并设为唯一待审退出指针，报名尝试版本相应增加，
**And** 报名状态仍为 CONFIRMED，仍在成功名单且占原名额，原报名提交时间/受理序号不变；不清除当前参加指针，不释放名额或补录他人，
**And** 申请人与发起者能读取真实请求，页面明确显示“报名成功，退出待审核”，不能只显示含糊的“待审核”或“已退出”。

#### AC-2.7-02 必填理由与非法请求整体拒绝

**Given** 退出申请包含未填、全空白、非文本或过长理由，或客户端试图指定目标用户、状态或处理时间，
**When** 服务端校验提交，
**Then** 按本稿待审建议，理由去首尾空白后须为 1–500 个 Unicode 码点；非法为 HTTP 400，明确指出输入问题，申请、指针、版本和回执不部分生效，
**And** 合法理由按纯文本保存/展示，不执行 HTML/脚本；不将理由混写为参加审核拒绝理由或活动变更说明，
**And** 请求仅使用会话本人及指定报名尝试；理由不能在普通日志、公共详情、成功名单或其他人的本人接口中出现。

#### AC-2.7-03 时间及资格以实际服务端状态为准

**Given** 报名可能已截止，活动可能开始，或当前报名/退出策略已与页面不同，
**When** 提交新的退出申请，
**Then** 报名截止后仍可在活动开始前提交；开始时及以后为 409 EXIT_CLOSED，不自动退出或自动通过，历史仍可查，
**And** 无当前成功尝试、尝试版本过时或已有待审退出请求为 409；当前允许自由退出时不创建受限退出申请，提示按实际策略刷新操作，
**And** 两种报名来源的成功者采用同一规则；尚未进入名单的 PENDING 不可申请退出，仍按 Story 2.5 撤回参加申请，
**And** 统一活动根行锁内独立 SQL 锁后取数据库 UTC 时间，最终写入前复核开始边界；等待锁或处理跨开始则整条命令回滚，不使用浏览器旧时间。

#### AC-2.7-04 本人撤回待审退出请求不退出活动

**Given** 活动未开始，本人仍是该活动当前成功者，目标退出请求为 PENDING，报名尝试的待审退出指针仍指向它，请求版本匹配，
**When** 本人按明确退出请求 ID、expectedVersion 和幂等键撤回退出申请，
**Then** 返回 HTTP 200，请求变为 WITHDRAWN、请求版本增加，清除待审退出指针并提升报名尝试版本，保留请求、理由、原提交时间和服务端撤回时点，
**And** 参加状态仍为 CONFIRMED、仍占位并在名单中，不释放名额；页面显示报名成功以及最近退出申请已撤回，不把它当作撤回参加申请，
**And** 撤回资格不要求仍在报名期，也不要求当前退出策略仍受限；到开始时关闭，未来策略变更后仍须由当前状态和指针裁决，不能使旧请求再次释放名额，
**And** 不提供直接修改待审理由的另一入口；如需更正可先撤回，再按当时资格提交新的退出请求，旧请求终态和理由保留。

#### AC-2.7-05 重复、并发及旧请求保护

**Given** 同人双击、两页并发提交/撤回、成功响应丢失，或同次报名后来出现新的退出请求，
**When** 使用同/异幂等键操作，
**Then** 同一报名尝试最多一个有效待审退出请求；不同键重复提交为 409 EXIT_REQUEST_PENDING，不新增并行请求或覆盖理由，
**And** 身份/目标权限检查后，同键同载荷成功回执先于新的状态/策略/时间门槛重放；同键不同载荷/目标为 409，跨活动复用键唯一冲突整条回滚后核对，
**And** 撤回只处理指定的 PENDING 请求及匹配指针/版本；旧终态、新请求、旧报名尝试或过时版本返回 409，不清除新的待审指针，不改写历史，
**And** 撤回后若仍具备提交资格，可产生新请求 ID、版本及提交时间；原幂等键只重放旧结果，页面随后读取当前请求，不将旧回执套到新请求，
**And** 与发起者通过/拒绝退出的真实竞争由 Story 2.8 接入，当前不冒充审核写流程已完成。

#### AC-2.7-06 本人操作与理由访问隔离

**Given** 匿名用户、另一参与者、活动发起者或该报名者本人请求操作/读取，
**When** 服务端核对会话、活动、报名尝试及退出请求归属，
**Then** 有效 CSRF 的匿名写请求及匿名私人读取为 401，缺少/伪造 CSRF 的写请求为 403；目标不存在、属于他人或不属于路径活动/尝试为 404，
**And** 只有申请人本人可提交和撤回自己的退出请求；发起者只能查看本活动的退出理由，不能代参与者申请或撤回；其本人参加时按相同参与者资格操作，
**And** 其他登录用户读取公开已发布活动的退出管理视图为 403，不因能管理别的活动而获权；私人响应 no-store，切换用户清除旧私人视图，
**And** 名单仍仅展示已批准的用户名、昵称和报名状态；理由放在专门的私人退出申请视图，不扩大名单或公共字段范围。

#### AC-2.7-07 本人和发起者可独立查看请求

**Given** 已提交或撤回过退出请求，
**When** 本人读取当前活动参与结果，或发起者从既有管理页查看退出申请，
**Then** 本人可看到当前待审请求及在无待审时最近退出请求的状态、时间、理由，明确它属于哪一次报名，不能误以为已经失去参加资格，
**And** 发起者的私人退出申请视图显示真实请求和理由、关联尝试/请求 ID 及版本；本故事不放置未实现的通过/拒绝按钮，后续审核据该请求定位，
**And** 待审退出仍计入 CONFIRMED 及成功名单，报名成功人数/剩余名额不变，退出待审提示不改变已确认的名单资料范围，
**And** 参加待审核人数仍只统计报名 PENDING，不把退出请求的 PENDING 混入参加待审统计，
**And** 到活动开始后未处理请求保持可查并提示处理已截止，不自动批准、退出或删除；读取为只读，不更新业务状态/版本或创建回执，
**And** 不等待跨活动完整历史才能查看本次请求及撤回结果，不新增退出结果通知、邮件或短信要求。

#### AC-2.7-08 事务失败及正常重启

**Given** 请求记录、待审指针、尝试版本或回执保存失败，或操作成功后正常重启，
**When** 分别核对回滚和重新读取，
**Then** 失败不留下孤立请求、指针或成功回执，不改报名资格和名额；死锁/锁超时等为可重试 503，不泄露 SQL 或私密理由，
**And** 统一活动根锁及同一 Spring JDBC READ_COMMITTED 事务保护请求/尝试/回执，响应未知时先查本人结果并按原键重试，重新执行须复核资格和实际时间，
**And** 正常重启保留请求/报名 ID、状态、理由、原提交/撤回时间、版本、指针和回执，待审不恢复为已退出或清空理由，
**And** 活动阶段提示可随真实时间推进，不能将提示变化误判为请求终态变化或数据丢失。

#### AC-2.7-09 独立验证与最小结构

**Given** 前十一条规范及本故事按顺序实施，尚无后续退出审核、重报、策略变更或取消能力，
**When** 用真实页面、会话及 MySQL 验证提交、读取及撤回，
**Then** 保存两种报名来源下受限退出、必填/空白/超长理由、截止后/开始边界、并发唯一、重复回执、撤回/重提与旧请求、理由权限、名单占位、回滚及正常重启的实际证据，
**And** 此时才创建当前所需 exit_requests、报名尝试的 pending_exit_request_id 及约束/版本增量；只提供 PENDING/WITHDRAWN 路径，不提前实现审批结果、候补或通知表，
**And** 回归自由退出、参加审核、待审撤回及现有读取；释放名额须等待退出获批，不能为给本故事制造成功结果而提前改变 CONFIRMED，
**And** 审核的真实竞争在 2.8、被拒后重提在对应拒绝流程、改策略后旧请求关闭及取消终态在 Epic 3 同时接入；实际环境/请求数/轮次如实记录，不用建议预算替代证据，
**And** 当前只是待审规范，理由长度建议尚未批准，没有运行结果，不直接标为 ready-for-dev 或软件验收通过。

#### 接口增量建议

| 接口 | 本故事用途 |
|---|---|
| POST /api/activities/{activityId}/registrations/{attemptId}/exit-requests | 本人提交；报名尝试 expectedVersion、reason、Idempotency-Key，首次 201 |
| POST /api/activities/{activityId}/exit-requests/{exitRequestId}/withdraw | 本人撤回；退出请求 expectedVersion、Idempotency-Key，成功 200 |
| GET /api/activities/{activityId}/my-participation | 扩展本人当前/最近退出请求，不改变当前成功参加的语义 |
| GET /api/activities/{activityId}/exit-requests | 仅本活动发起者私人读取退出请求；不合并进入公开详情或公开名单 |

精确字段和错误码先进入共同契约，两位成员核对后实施。提交和撤回是不同对象/版本操作：提交检查报名尝试版本，撤回检查退出请求版本及其当前指针，不能互换。采用既有 BIGINT 字符串、UTC 时间和北京时间展示、会话/CSRF 及回执约定。

理由在当前待审时不直接编辑，撤回后可重新提交仍是按当前资格创建新请求；被拒后重提的实际路径在 2.8 补齐。退出请求终态保留，不能复用旧请求给新报名退出。先到先得/参加审核模式均不改变受限退出需要理由和审批的规则。
