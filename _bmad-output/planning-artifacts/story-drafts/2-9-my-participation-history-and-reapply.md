### Story 2.9: 查看本人报名历史并在允许时重新报名

As a 已提交过参加申请或参加过活动的同学，
I want 集中查看自己的报名和退出历史，并在仍开放报名时重新申请，
So that 能了解当前资格与过去结果，重新参加也不会误用旧名额或排队顺序。

本文件保留已批准审阅快照。用户于 2026-11-27 回复“通过，汇总后就停止”，批准 Story 2.9（D-031）；正式维护入口为 epics.md，本文件不再独立演进。规范获批不等于实现或测试完成，汇总后按用户要求停止。前置为十三条已批准规范；复用前置故事真实产生的拒绝、撤回和退出结果，交付完整本人历史及新一轮报名，不依赖未来变更/队列/通知代码。Epic 2 仍处于固定活动设置阶段；未来改模式、候补和取消的增量由 Epic 3 与相应入口同时接入。

D-031 已确认“我的报名”按本人最近提交时间从新到旧显示活动，同刻按活动 ID 数值倒序；同一活动内按原申请时间倒序、同刻按受理序号数值倒序展示历史。当前有效资格单独突出，不能靠历史列表第一行或前端猜测。初版不新增搜索、筛选或分页。

**Acceptance Criteria:**

#### AC-2.9-01 登录用户集中查看本人活动记录

**Given** 用户已登录，可能没有参加记录，也可能对多个活动有历史或当前申请，
**When** 从导航进入“我的报名”，
**Then** 只读取本人提交过的活动，每场活动显示标题/入口、当前报名模式、时间阶段、当前资格及最近结果，当前无有效申请与仍待审/成功明确区分，
**And** 按 D-031 已确认约定，以本人该活动最近申请的原提交时间倒序、同刻按活动 ID 数值倒序稳定排列，服务端统一排序；不按 JavaScript 字符串 ID 重新排序，
**And** 无记录返回 HTTP 200、空集合和真实空状态；加载/失败/身份过期分别显示，不把查询失败当成未报名，也不回退到演示数据，
**And** 既有活动详情的本人最小结果入口继续可用，不强制跳转新页面才能查询本次操作结果。

#### AC-2.9-02 每次报名和退出请求独立保留

**Given** 同一活动存在本人多次报名尝试及各次关联的退出请求，
**When** 展开本人该活动的历史，
**Then** 按 D-031 已确认约定以原申请时间倒序、同刻按活动受理序号数值倒序展示每次真实尝试，包含该次 ID、提交时间、状态及已有处理时点/可见结果，
**And** 按报名尝试关联显示各次退出申请的原理由、提交/撤回/审核状态和时间，不把另一轮退出请求贴到当前报名；退出请求可按提交时间倒序、同刻请求 ID 数值倒序，
**And** 参加 REJECTED 与退出请求 REJECTED、撤回参加与撤回退出、直接 EXITED 与退出获批导致 EXITED 清楚区分，不将退出待审显示为已退出，
**And** 当前参加指针为服务端当前资格依据，终态历史不能充当有效资格；发起者申请视图保留多次尝试，但成功名单和人数只统计当前 CONFIRMED，不按历史条数占位，
**And** 截止或开始后历史仍可查，不因操作入口关闭删除记录；未来取消后的历史与原因展示随 Epic 3 接入，不能届时用过滤已发布活动的方式丢掉历史。

#### AC-2.9-03 只有无当前资格的允许终态可重报

**Given** 本人前次参加尝试为 REJECTED、WITHDRAWN 或 EXITED，当前参加指针为空，活动已发布、未持久关闭且当前处于报名窗口，
**When** 在活动详情或本人记录中明确点击“重新报名/重新申请”，
**Then** 服务端允许按当前模式、名额和资格重新受理，不因有失败/退出历史永久禁止参加，
**And** 新申请仍要求报名开始≤数据库当前时间＜截止；已截止不因重报重开，开始后、未来取消后不得重报，
**And** 锁后以独立 SQL 读取数据库 UTC 时间，在分配名额前及最终写入前复核适用边界，等待锁或处理中跨截止则整条新申请回滚，
**And** 页面无当前资格不代表必然可重报，时限、模式或容量不满足时显示真实原因，不自动提交或悄悄恢复旧申请。

#### AC-2.9-04 新一轮使用新记录与新受理顺序

**Given** 重报已满足前述资格和明确操作意图，
**When** 复用统一报名端点提交新的幂等键与当前期望报名模式，
**Then** 返回 HTTP 201，创建新报名尝试 ID 和版本，服务端重新赋值受理时间并分配新的活动内唯一递增受理序号，将既有唯一参与槽位的当前指针指向新尝试，
**And** 不修改旧尝试的终态、时间/序号、处理信息或关联退出请求，不创建第二个同人同活动槽位，不复用旧排名，
**And** 当前先到先得时仍需有可分配名额才为 CONFIRMED，满额失败不进入候补；当前审核模式受理为 PENDING、不占位，满额仍可申请，
**And** 期望模式不符为 409 并刷新，不由客户端覆盖活动模式；未来队列迁移必须将该统一入口接入旧候补优先，不能因来自“重报”按钮绕过 FR-23。

#### AC-2.9-05 有效申请与退出待审不允许重报

**Given** 本人已有当前 PENDING 或 CONFIRMED，或成功报名上有待审/被拒/已撤回的退出请求但仍未真正退出，
**When** 试图重新报名，
**Then** 返回 409 ALREADY_PARTICIPATING，不新建尝试、不重复占位，页面显示真实当前资格，
**And** 退出请求被拒或被撤回不等于参加终止，不能把退出请求的终态当作报名尝试可重报的依据，
**And** 后续引入 WAITLISTED 时同样视为当前有效申请，须先按规则撤回才能重新申请；本故事不预建候补或假造该写流程，
**And** 当前为成功者但无法参加时仍按活动退出策略操作，不能借重报请求替自己腾出或额外占用名额。

#### AC-2.9-06 过时的重报请求不能创建更多轮次

**Given** 两页同时重报、网络重试，或旧页面仍持有更早一轮的终态，
**When** 服务端执行新的报名命令，
**Then** 按 D-031 已确认约定，重报请求带 expectedPreviousAttemptId，指向本人已看到的最近一次允许终态；获得活动锁后须与当前无有效申请及服务端最近尝试匹配，过时为 409 STATE_CONFLICT，
**And** 首次申请缺省/空的 expectedPreviousAttemptId 仅在无既往尝试时允许新执行；已有历史却不声明前次尝试不能被当作首次报名，防止旧首次请求在参加结束后意外新建一轮，
**And** 同键同目标/原载荷成功回执经身份/目标权限检查后先于新的资格/时限/前次尝试检查重放，不重复新建；同键不同载荷/目标为 409，回执重放后读取当前真实状态，
**And** 同一前次尝试的并发重报最多受理一轮；即使该新一轮随后又结束，较旧页面仍不能用旧前次 ID 创建第三轮，必须刷新后明确再申请，
**And** 既有成功回执载荷摘要不被新增控制字段改写，原键重试沿用原请求；跨活动复用键冲突整条回滚后核对，所有新执行都守同一活动锁和当前指针唯一性。

#### AC-2.9-07 旧参加和退出操作不影响新一轮

**Given** 已有真实重报尝试，旧通过/拒绝、撤回参加、直接退出、退出请求提交/撤回/审核的旧请求可能再次到达，
**When** 按各自目标 ID、版本、指针及幂等约定执行，
**Then** 非重放的新执行不能将旧尝试/旧退出请求的操作套到当前新尝试，旧终态或指针不匹配返回 409，不清新指针、不改新状态、不重复释放或占用，
**And** 合法原成功回执仅重放历史操作结果及对应版本，不再执行业务，客户端刷新后显示新一轮当前状态，不能用旧“退出成功”覆盖新一轮成功，
**And** 发起者管理页以确切尝试 ID 和版本处理每轮申请，不只按用户 ID 审核；当前成功人数、待审人数和名单不能重复计入旧历史，
**And** 旧操作、重启或失败重报不能回退已提交的受理序号进度或覆写既有有效队列键；失败事务尚未受理的序号增量随事务回滚，沿用既定原子性，未来队列公平性仍须随 Epic 3 实测。

#### AC-2.9-08 本人历史和理由不越权

**Given** 匿名用户、另一参与者或活动发起者尝试读取个人记录，
**When** 请求“我的报名”或某活动本人历史，
**Then** 身份仅取会话，匿名为 401，接口不接受 userId/actorId 指定他人；不返回别人的报名、退出理由或拒绝结果，
**And** 某场活动发起者仍只可使用本活动的私人管理入口，不能因其发起者身份读取任一用户的跨活动个人历史；公开详情不含这些私人集合，
**And** 私人响应 no-store、切换用户清空旧私人视图；理由按已确认权限和纯文本显示，不返回密码/编码值/会话，普通日志不记录理由，
**And** 对不存在或不可见目标沿用 404 等既有约定，读查询无业务写入、自动审批、补录或成功回执。

#### AC-2.9-09 失败回滚和正常重启保持历史完整

**Given** 新尝试、槽位指针、序号或回执写入失败，或重报成功后正常重启，
**When** 分别核对事务回滚与重新登录读取，
**Then** 失败不留下半次重报、额外占位、错误指针或成功回执，不改旧终态和原始历史；容量失败或截止失败仍保留原可查历史，
**And** 死锁/锁超时等为可重试 503，不泄露 SQL，响应未知时先查询并按原键重试，重新执行须重新核对前次 ID、状态和实际时间，
**And** 正常重启保留所有尝试及退出请求关联、理由/结果、原始时间/序号、当前指针/状态和回执，页面显示新一轮当前资格及真实旧历史，
**And** 不用历史复制、演示数据或浏览器缓存重建当前状态，不把保持会话作为历史持久性的前提。

#### AC-2.9-10 独立验证与 Epic 2 边界

**Given** 前十三条规范及本故事按顺序实施，未来已发布变更、候补迁移、取消和通知尚未实施，
**When** 用真实页面、会话及 MySQL 验证本人历史及重报，
**Then** 保存参加被拒/撤回/自由退出/退出获批后的真实重报，当前两种模式的正确结果、满额/截止、退出待审与退出被拒不能重报、多轮记录/理由关联、并发唯一、过时前次 ID、所有旧操作重放/新执行、隐私、失败回滚和正常重启的实际证据，
**And** 复用现有槽位/尝试/退出请求/回执，仅增量查询及确需索引/控制字段，不预建未来队列、变更或通知表，不要求未来故事代码，
**And** 当前模式切换、候补、改期不可逆关闭和整场取消的真实交错在 Epic 3 与对应入口一并验证；固定设置下的本人历史及参与闭环不因此依赖未来实现，
**And** 实际环境、请求数/轮次及结果如实记录，不能将测试夹具、建议预算或规范审阅当作软件已通过；当前不直接标为 ready-for-dev，Epic 2 汇总与进入 Epic 3 仍需本条批准后的覆盖核对和交接确认。

#### 已确认的接口与契约增量

| 接口 | 本故事用途 |
|---|---|
| GET /api/my/participations | 会话本人活动分组及当前/最近状态；无记录 200 空集合，初版不筛选/分页 |
| GET /api/activities/{activityId}/my-participation/history | 会话本人各次报名及关联退出请求，当前资格明确；无本人记录 200 空集合 |
| POST /api/activities/{activityId}/registrations | 复用统一入口，重报带新 Idempotency-Key、expectedEnrollmentMode、expectedPreviousAttemptId，受理 201 |

expectedPreviousAttemptId 是防止过时操作的控制字段，不是可指定新报名身份/时间/名额或恢复旧顺序的字段；首次无历史时可空/缺省。新请求执行前校验前次终态和当前指针，成功回执重放先于这些新执行条件；不得因协议增量破坏已有原请求/回执的重放语义。精确 JSON、错误码、字段兼容和排序约定先进入共同契约，两位成员核对后实施。

本人当前活动最小结果、完整历史和发起者管理视图共用相同当前指针/状态含义；历史仅证明曾发生的操作，不赋予当前成功资格。显示方案及控制字段已由 D-031 确认；该批准不代表已完成实现或运行验证。不新增通知渠道、永久禁止重报或虚构用户研究结论。
