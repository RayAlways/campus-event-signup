### Story 1.4: 发布活动并选择初始报名模式和退出策略

As a 已经准备好活动草稿的发起者，
I want 完善必填信息，选择报名模式和退出策略并发布，
So that 同学可以通过公开详情了解活动及参与条件。

本条为待审阅草稿。前置为已实施的 Story 1.1–1.3，现有字段、长度和可选结束时间沿用 D-019，不重新提出。下方发布必填项及当前时间资格是本次新增建议。为避免反向依赖未来的 Story 1.5，本故事同时交付最小公开详情；公开活动列表、完整状态及人数展示由 1.5/对应报名故事增量承接，不把一个故事等同于 FR-04/FR-05 全部场景已完成。

**Acceptance Criteria:**

#### AC-1.4-01 本人完整草稿可以发布

**Given** 当前用户已登录，有有效 CSRF 令牌，草稿属于本人且仍为 DRAFT，字段完整合法、版本未过期，
**When** 带幂等键与 expectedConfigVersion 提交发布，
**Then** 返回 HTTP 200、原活动字符串 ID、PUBLISHED 状态、配置版本和发布时间，活动不会另建第二份记录，
**And** 发起者、已保存字段、报名模式和退出策略按服务端当前草稿生效；版本提升，保存不可由客户端伪造的发布时间，
**And** 页面显示真实发布结果和可打开的公开详情链接，不依赖未来列表或报名接口来证明发布成功。

#### AC-1.4-02 不完整草稿不能被发布

**Given** 草稿缺少下表任一发布必填项，或包含非法字段/关系，
**When** 请求发布，
**Then** 返回 HTTP 400 及明确的缺失/非法字段，仍为原 DRAFT，旧内容和版本不变，
**And** “未命名草稿”的界面占位不能充当实际标题；模式、退出策略不得自动补成默认选项，
**And** 未保存的表单更改必须先保存成功再发布，页面不能无提示地把旧版本内容发布，
**And** 不完整草稿仍可按 Story 1.3 修改，发布失败不锁死或删除草稿。

#### AC-1.4-03 发布时复核当前时间

**Given** 时间字段满足报名开始＜报名截止≤活动开始，结束未填或晚于开始，
**When** 在活动锁内检查发布条件及最终写入边界，
**Then** 报名截止必须晚于实际校验时点；已到截止或活动已开始的草稿返回 HTTP 409，不发布，
**And** 允许报名开始早于或等于当前时点，只要尚未截止；也允许未来才开始报名，
**And** 报名截止等于活动开始仍合法，不人为添加必须存在的“截止后审核窗口”，
**And** 等待锁或处理中跨过截止时重新取时并回滚，不能用页面或请求刚到达时的旧时间放行；DRAFT 发布失败不生成已对外关闭报名的事实。

#### AC-1.4-04 初始两种模式与两种退出策略独立

**Given** 发起者已在草稿中明确选择一种报名模式和一种退出策略，
**When** 分别发布四种组合，
**Then** 先到先得/参加审核与自由退出/退出须审核的四种组合均可保存为已发布设置，并在公开详情清晰展示，
**And** “参加审核”由发起者后续审核报名者，不是发布活动本身要找管理员审批；没有新增组织者资格门槛，
**And** 发布本身不等于发起者报名、不自动创建参加记录，不决定发起者以后能否手动报名自己的活动。

#### AC-1.4-05 发布权限与草稿入口保持隔离

**Given** 另一用户或匿名客户端知道草稿 ID，或请求试图伪造 owner/status，
**When** 读取私有草稿或发布，
**Then** 他人草稿按既定约定 404，匿名有效 CSRF 请求为 401，缺少/伪造 CSRF 的写请求为 403，数据不变，
**And** 发布仅接受约定的版本等控制字段，不通过发布接口顺带覆盖 owner、标题或模式，
**And** 发布后不再出现在本人草稿列表，原草稿修改接口不能继续改它；已发布编辑、切换和取消仍由 Epic 3 承接。

#### AC-1.4-06 重试和并发不能重复发布或覆盖内容

**Given** 同一草稿可能被两个页面保存/发布或出现网络重试，
**When** 执行这些命令，
**Then** 同键同载荷的成功回执先于新命令的状态/时限检查重放，不重复发布时间、版本或状态变化；同键不同载荷为 409，
**And** 不同键再次发布已发布活动，或旧版本发布，返回 409，不创建副本、不覆盖新内容，
**And** 保存先成功时旧版本发布失败；发布先成功时后续草稿保存失败；所有变更遵守同一活动锁和事务。

#### AC-1.4-07 发布后可访问最小公开详情

**Given** 活动已成功发布，或另一个 ID 仍为 DRAFT/不存在，
**When** 未登录或已登录用户通过公开详情链接访问，
**Then** 已发布活动返回 HTTP 200，展示标题、说明、地点、发起者展示名、时间、容量、报名模式和退出条件，
**And** DRAFT 和不存在的 ID 均为 404，不向匿名用户回退到私有草稿内容，
**And** 不暴露账号秘密、完整名单、私密申请或回执，不执行文本中的 HTML/脚本，
**And** 本故事不提供假报名按钮、模拟成功人数或虚构剩余名额；活动列表和后续人数/报名能力由对应故事真实接入。

#### AC-1.4-08 失败原子性与重启恢复

**Given** 发布过程中可能发生数据库错误/锁超时，或成功发布后正常重启，
**When** 分别检查失败回滚及重启后的公开详情，
**Then** 失败时状态、版本、发布时间和成功回执不部分生效，不出现页面说成功而记录仍是草稿，
**And** 已成功发布的状态、设置、时间与原 ID 在重启后保留；重新登录后也不能借原草稿接口再次发布/修改，
**And** 初次发布不要求填写“活动变更说明”，也不生成不存在的原名单通知；后续修改须说明和通知的已确认规则不因此取消。

#### AC-1.4-09 独立交付并回归原流程

**Given** 前三条故事已实施，本故事没有未来的公开列表、报名、模式迁移或通知功能，
**When** 用真实页面、会话和 MySQL 验证发布，
**Then** 保存完整/缺项、已截止边界、四种设置组合、跨用户拒绝、版本/重试/并发、公开详情隐私及重启恢复的实际证据，
**And** 只增量扩展当前需要的 activities 字段及既有回执，不预建报名、候补、退出、变更通知业务表，
**And** 注册、登录/退出、草稿保存回归通过；没有因新增公开接口而放开草稿或整段 `/api` 的权限，
**And** 不把上述计划写成已经执行的测试，当前不直接标记 ready-for-dev。

#### 本次发布规则建议（待审阅）

| 项目 | 建议 |
|---|---|
| 发布必填 | 标题、活动说明、地点、容量、报名开始、报名截止、活动开始、报名模式、退出策略 |
| 仍可不填 | 活动结束时间；填入时必须晚于活动开始 |
| 文本与容量 | 沿用 D-019 的 100/5000/200 字符及正整数容量，不重新加人数上限 |
| 时间资格 | 截止须晚于实际发布校验时点，因此不能发布已截止或已开始的活动；报名可以已经开始，也可以尚未开始 |
| 发布与审批 | 仅本人操作，无平台审批；参加审核模式只约束后续报名申请 |

时间资格与发布必填为本条新建议，不改变私有草稿可暂存过去时间的已确认规则，也不提前决定已发布活动如何改期到过去。

#### 接口与交付建议

| 接口 | 用途 |
|---|---|
| POST /api/activities/{activityId}/publish | 会话本人发布已保存 DRAFT；幂等键及 expectedConfigVersion；成功 200，缺项/非法 400，状态/版本/已截止冲突 409 |
| GET /api/activities/{activityId} | 最小公开已发布详情；公开字段投影，不读取私有草稿详情；未发布/不存在 404 |

发布成功响应需含公开详情入口，精确字段及错误码纳入实施前的共同接口契约。公开列表由 Story 1.5 创建；本故事提供直接访问的详情，使发布可独立验证，而不是等待未来故事再变成可用功能。取消后的公开展示由 Epic 3 增量承接，不借当前故事创建取消入口。
