### Story 2.8: 发起者审核退出请求并由参与者查询结果

As a 活动发起者，
I want 在活动开始前查看理由并通过或拒绝有效的退出请求，
So that 请求人明确知道是否已经退出，成功名单和实际占用名额同步保持正确。

本稿待审。D-029 只批准 Story 2.7 及退出理由输入限制，不批准本稿。前置为十二条已批准规范；在既有私人退出申请视图接入审核，并扩展既有本人结果查询。当前活动设置保持不变，不依赖未来重报、变更、候补和通知代码。

本故事沿用已确认的退出申请理由，不新增审核说明或证明材料字段。参加申请审核与退出请求审核使用不同对象、状态和入口，不能互相复用终态或误改参加资格。

**Acceptance Criteria:**

#### AC-2.8-01 退出获批才结束参加并释放一次名额

**Given** 发起者已登录且持有效 CSRF，活动已发布、未开始，目标退出请求为本活动 PENDING 且版本匹配，其关联报名仍是当前有效 CONFIRMED，待审退出指针指向该请求，
**When** 发起者按退出请求 ID、expectedVersion 及幂等键提交通过，
**Then** 返回 HTTP 200，请求变为 APPROVED、请求版本增加，保存服务端审核人/时点；关联报名变为 EXITED、报名版本增加，并记录退出时点，
**And** 同事务清除待审退出指针及当前参加指针，保留原报名/请求、理由及原提交时间/序号，不删除历史，
**And** 当前成功名单移除该人，CONFIRMED 数减少恰好一人、剩余名额增加恰好一个，不修改活动容量/配置版本，不生成另一条退出记录，
**And** 本人查询同时明确“退出申请已通过、已退出活动”，不能请求已通过却仍占位，或报名已退出而请求仍待审。

#### AC-2.8-02 退出被拒保持成功和占位

**Given** 同样满足活动归属、开始前、有效请求/报名指针及请求版本条件，
**When** 发起者提交拒绝退出请求，
**Then** 返回 HTTP 200，请求变为 REJECTED、版本增加并保存审核人/时点，清除待审退出指针并提升报名尝试版本，
**And** 报名仍为 CONFIRMED，当前参加指针、成功名单和名额保持，不触发释放、补录或通过其他人的申请，
**And** 本人结果显示“报名成功，退出申请已拒绝”，不得误显示“参加申请已拒绝”或“已退出”；原退出理由保留且不被审核改写，
**And** 拒绝退出只处理已有请求，不能代他人提出请求、撤回请求或直接移出名单，本故事不新增必填/选填审核理由字段。

#### AC-2.8-03 审核既有请求截至活动开始前

**Given** 退出请求已受理，报名可能已截止或当前时间接近活动开始，
**When** 执行新的通过或拒绝命令，
**Then** 报名截止后仍可审核既有有效请求；服务端时间等于或晚于开始时返回 409 EXIT_REVIEW_CLOSED，不自动通过、拒绝或退出，历史仍可读取并提示处理已截止，
**And** 在统一活动行锁内用独立 SQL 锁后取数据库 UTC 时间，改变资格前及最终写入前再次复核开始边界，等待锁或处理跨开始时整个命令回滚，
**And** 不因先到先得/参加审核模式不同改变退出审核规则；审核的是已经存在的有效请求，不把当前退出策略仍受限作为额外前提，
**And** 未来改为自由退出后的真实竞争、旧请求关闭和整场取消由 Epic 3 随变更入口共同接入；请求已关闭、指针失效或报名已结束时不能再次释放名额。

#### AC-2.8-04 与本人撤回或另一审核竞争

**Given** 本人撤回退出请求与发起者通过/拒绝同时执行，或两个页面对同一请求做不同审核，
**When** 命令竞争同一活动根锁并核对当前指针/状态/请求版本，
**Then** 同一请求只提交一个有效结果；撤回先成功则后续审核 409，报名继续成功占位，
**And** 通过先成功则后续撤回/拒绝 409，报名保持 EXITED；拒绝先成功则后续通过/撤回 409，报名保持 CONFIRMED，不能改写已有终态，
**And** 请求状态、报名状态/版本、两个指针和成功回执在同一 Spring JDBC READ_COMMITTED 事务中改变，不产生部分组合，
**And** 申请人和发起者在冲突后刷新真实结果，不以页面按钮是否可点代替服务端校验，不使旧请求影响后来的新请求。

#### AC-2.8-05 重试、旧请求与名额并发

**Given** 成功响应丢失、重复点击、旧版本请求，或退出获批与其他用户报名/参加审核同时发生，
**When** 使用同/异幂等键执行审核，
**Then** 身份/目标权限检查后，同键同载荷成功回执先于新命令的状态/时限门槛重放，只返回原结果，不重复释放；同键不同目标/载荷为 409，跨活动复用键唯一冲突整条回滚后核对，
**And** 无原成功回执的新命令须验证请求属于该活动/尝试、仍 PENDING、版本匹配、参加当前指针和待审退出指针均正确；旧终态或错误当前指针为 409，不清除新请求或新报名的指针，
**And** 所有名额操作遵守同一活动锁，成功人数采用 CONFIRMED 真值，释放后仍不能超容量或为同一次退出重复腾出名额，
**And** 审核模式出现空位不自动通过参加待审；先到先得的新报名仍守截止，未来旧候补同步补录在 Epic 3 接入同一释放事务，当前不伪称完整公平队列已实现。

#### AC-2.8-06 被拒后可重新提交退出申请

**Given** 原退出请求已被拒，用户仍是当前成功参加者，无其他待审退出请求，活动未开始且当前仍要求审核退出，
**When** 用户刷新取得当前报名版本，再按 Story 2.7 提交理由和新的幂等键，
**Then** 创建新的退出请求 ID、版本和提交时间，沿用已确认的 1–500 Unicode 码点理由规则，旧 REJECTED 请求及理由/审核信息保留，
**And** 仍最多一个有效 PENDING，新请求不会变成旧请求的修改或复活；旧审核/撤回请求或旧回执不得处理新请求，
**And** 新申请期间仍 CONFIRMED 并占位；退出获批后已经 EXITED 的人不能再对原报名提出退出请求，
**And** 此处是同一次参加的退出请求重提，不等于退出后重新报名；后者由 Story 2.9 提供，不等待它才能重新申请退出。

#### AC-2.8-07 权限与私人结果读取

**Given** 匿名用户、普通参与者、另一活动发起者或本活动发起者请求审核，
**When** 服务端核对身份、活动和退出请求关联，
**Then** 有效 CSRF 的匿名写请求为 401，缺少/伪造 CSRF 为 403；仅本活动发起者可审核，他人对公开已发布活动的管理写请求为 403，
**And** 活动不存在/不可见为 404；核实活动管理权后，退出请求不存在或不属于该活动为 404，不泄露别的活动请求，不接受客户端伪造审核人、状态或时间，
**And** 本人通过既有最小结果入口看到当前参加与当前/最近退出请求；发起者通过私人退出视图看到真实结果和原理由，理由及结果不进入公共详情或他人记录，私人响应 no-store，
**And** 发起者自己参加本活动且已提交有效退出请求时，也可按本活动发起者权限处理，仍须满足同一状态、版本和时限规则，不自动通过，
**And** 本人未获批前仍在名单，拒绝后继续在名单；获批后只保留历史，名单显示字段和原报名时间排序沿用 D-025，不按退出审核时间重排。

#### AC-2.8-08 失败原子性和正常重启

**Given** 请求状态、报名/版本、指针或回执写入出错，或审核成功后正常重启，
**When** 分别检查回滚和重新登录查询，
**Then** 失败不留下半次审核、提前退出、错误释放或成功回执；死锁/锁超时等为可重试 503，不泄露 SQL 或私密理由，
**And** 响应未知时先查真实结果再按原键重试，无成功回执的新执行须重新取锁/取时并验证资格，不绕过开始边界，
**And** 正常重启保留 APPROVED/REJECTED、审核人/时点、原理由、报名状态/版本、两个指针和回执，名单与名额继续反映真实结果，
**And** 不靠清空数据、前端缓存或永久会话恢复结果，历史原提交时间/序号不因审核或重启改变。

#### AC-2.8-09 独立验证与后续边界

**Given** 前十二条规范及本故事按顺序实施，尚无未来重报、策略变更、迁移补录或取消功能，
**When** 用真实页面、会话及 MySQL 验证退出审核，
**Then** 保存两种报名来源的通过/拒绝、占位/释放、截止后/开始边界、撤回竞争、重复/旧请求、拒绝后重提、发起者本人退出审核、隐私、结果读取、回滚及正常重启的实际证据，
**And** 仅为当前 exit_requests 增加审批终态和审核字段及必要约束，扩展报名状态/指针和既有回执，不预建通知或候补表，
**And** 回归自由退出、参加审核、参加撤回、退出申请提交/撤回和所有相关读取；与真实新报名尝试的旧请求隔离在 2.9 补齐，当前可用测试库夹具核对保护，不冒充重报已完成，
**And** 实际请求数/轮次/环境如实记录，A-6 建议不当作实测；当前只是待审规范，没有运行结果，不直接标记 ready-for-dev 或软件验收通过。

#### 接口增量建议

| 接口 | 本故事用途 |
|---|---|
| POST /api/activities/{activityId}/exit-requests/{exitRequestId}/approve | 发起者通过退出；退出请求 expectedVersion、Idempotency-Key，成功 200 |
| POST /api/activities/{activityId}/exit-requests/{exitRequestId}/reject | 发起者拒绝退出；同上，成功 200；不新增审核理由字段 |
| GET /api/activities/{activityId}/my-participation | 当前参加状态及当前/最近退出请求结果，正确区分“退出被拒”与“参加被拒” |
| GET /api/activities/{activityId}/exit-requests | 既有私人请求列表增量显示审核结果/时点，原理由仅授权者可见 |

审核 expectedVersion 指退出请求版本；服务端同时检查该请求的报名关联、当前参加指针与待审退出指针。精确 JSON/HTTP/错误码先入共同契约，两位成员核对后实施；其余 BIGINT 字符串、UTC 时间、北京时间显示、会话/CSRF、幂等和秘密保护沿用既有约定。

获批真实释放只发生一次；拒绝、撤回、提交和读查询均不释放。未来改为自由退出时的本人直退须同时关闭旧待审请求，取消须关闭所有待处理请求及停止业务；这些增量由 Epic 3 与相应入口一起交付，不让当前故事反向依赖未来代码。不新增审核结果通知渠道或独立平台管理员。
