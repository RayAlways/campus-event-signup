## ADR-001 Vue＋Spring Boot＋MySQL 的分层单体

- **背景与状态：**用户本人使用过三项技术，并明确选择推荐方案和快速初稿；高层组合已接受，具体版本是核查后的种子建议。
- **决定：**前端 Vue SPA、后端一个 Spring Boot 应用、MySQL 持久化；模块化分层，只有后端裁决业务状态（AD-1）。
- **未采用的备选与理由：**Spring MVC＋Thymeleaf 可减少前端构建，但用户选择了前后端分离；微服务会把容量、名单、退出和通知拆成跨服务一致性问题，两人短周期没有相应收益。
- **代价：**需要统一 DTO、错误码、状态与联调；交付构建需要前后端两步。
- **验证计划：**按共同契约完成一条从页面到持久化的纵向路径；前端绕过按钮直接请求时仍受到业务约束。
- **关联：**FR-01 至 FR-23；D-014；[Vue 官方脚手架](https://vuejs.org/guide/quick-start.html)、[Spring MVC 官方说明](https://docs.spring.io/spring-boot/reference/web/servlet.html)。

## ADR-002 活动行锁＋共享事务＋名单计数

- **背景与状态：**最后一席、批准退出、扩容、模式切换共享同一名额；技术建议。
- **决定：**所有活动写命令先锁活动根，在同一 READ_COMMITTED 事务内处理，已占名额直接统计 CONFIRMED；采用 Spring JDBC 明确表达锁、查询及批量写（AD-2）。
- **未采用的备选与理由：**只用 Java synchronized 无法约束绕过该代码的数据库写入，也不能代替数据库回滚；只对人数做条件加减无法单独保证队列和状态迁移；乐观锁＋全流程重试也可实现，但需要为复杂迁移重放更多路径，本版不选；仅依赖 ORM 隐式 flush 的方案不利于审查实际加锁顺序。
- **代价：**同一活动的写操作串行化，热点活动吞吐受限；需保持事务短小，未来规模增长时再以实测决定是否改造。
- **验证计划：**真实 MySQL 上争抢最后一席、交错退出和报名、并发取消与审核；核对人数、队列和回滚，无超额或重复释放。
- **关联：**NFR-01、NFR-04；FR-07、FR-10、FR-19、FR-23；[InnoDB 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。

## ADR-003 当前槽位、报名尝试及退出请求分别建模

- **背景与状态：**同一人可以重报，退出待审仍占位，旧请求不能作用于新一轮申请；技术建议。
- **决定：**活动/用户唯一槽位指向当前 attempt；每次重报新建 attempt；退出请求另表保存理由和历史，待审指针最多一个（AD-3）。
- **未采用的备选与理由：**覆盖一行报名记录会丢失重报前的状态与申请时间；把 EXIT_PENDING 直接替换 CONFIRMED 会使“成功人数”的定义分裂；以报名表和成功名单表分别作为真值容易出现只更新一边。
- **代价：**多一个当前指针及归属校验，查询需要关联表；Flyway 需处理指针外键创建顺序。
- **验证计划：**拒绝/撤回/退出后重报，检查新时间与旧历史；重放旧 attempt 或旧退出请求的审核命令不能改变新记录。
- **关联：**FR-12 至 FR-19、FR-22；NFR-01、NFR-02。

## ADR-004 在命令内同步补录并持久化截止事实

- **背景与状态：**用户明确要求旧申请优先、自动补录到开始前、改期不重开已截止报名；技术建议。
- **决定：**活动锁下分配受理时间与序号；触发空位或模式变化的同一事务完成按序补录。锁后另取数据库时间，并保存报名已关闭事实（AD-4）。
- **未采用的备选与理由：**前端刷新或轮询才能递补会把进度交给用户在线状态；定时补录存在空位窗口和额外竞态；以客户端时间排序可被伪造；仅用“当前时间小于修改后的截止”会意外重开已经关闭的报名。
- **代价：**大批模式迁移可能延长持锁时间；本版面向小型活动，规模与等待指标需实测，不假设无限候补量。不能为了缩短事务而直接拆成会改变优先规则的异步队列。
- **验证计划：**有旧候补时并发新报名、先到先得/审核往返切换、截止后改期、等待锁跨越开始时间；检查旧键保持、补录截止和关闭事实。
- **关联：**D-010 至 D-013；FR-06、FR-07、FR-23；[MySQL 时间函数](https://dev.mysql.com/doc/refman/8.4/en/date-and-time-functions.html)。

## ADR-005 服务端 Session、同源与 CSRF

- **背景与状态：**注册用户按活动取得权限，退出登录后旧凭据必须停止写入；技术建议。
- **决定：**Spring Security HttpSession、HttpOnly Cookie、CSRF、服务端所有权校验；开发代理与交付同源；密码单向编码（AD-5）。
- **未采用的备选与理由：**localStorage JWT 需要额外处理注销撤销、令牌存储与泄露面，本项目无跨服务认证需求；仅隐藏管理按钮不能阻止直接请求；关闭 CSRF 来解决联调问题会破坏 Cookie 会话的保护。
- **代价：**前端需按登录周期取得 CSRF 令牌；应用重启可能需要重新登录，业务数据仍必须保留。多实例共享会话本轮不处理。
- **验证计划：**退出后复用旧 Cookie、伪造 owner/user、读取他人通知/理由、缺少 CSRF 的写操作都应失败；正确身份与令牌仍能完成正常流程。
- **关联：**FR-01、FR-02、FR-16、FR-19、FR-21；NFR-02；[Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)、[PasswordEncoder](https://docs.spring.io/spring-security/reference/servlet/authentication/passwords/password-encoder.html)。

## ADR-006 站内通知与业务变更同事务

- **背景与状态：**站内通知就是本地数据库记录，PRD 不允许变更成功但遗漏原名单用户；技术建议。
- **决定：**活动锁下先取原成功名单，再原子写业务变化、不可变变更记录和去重通知（AD-6）。
- **未采用的备选与理由：**提交后直接调用异步监听器，进程中断时可能丢通知；事务 outbox 可处理外部消息投递，但当前无外部通知，增加转发器和补偿流程没有必要；发送邮件/短信超出第一版渠道。
- **代价：**通知接收人数影响本次事务写量；需验证失败回滚，不把通知失败吞掉。
- **验证计划：**人为使通知插入失败，业务编辑/取消也必须回滚；重复提交只产生一组通知，模式切换新补录者不被错误计为原名单用户。
- **关联：**FR-06、FR-20 至 FR-23；NFR-04；[Spring 共享物理事务语义](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/tx-propagation.html)。

## ADR-007 单一接口契约、版本检查与幂等回执

- **背景与状态：**两人并行开发会遇到 ID 精度、状态拼写、旧页面、断网重试；技术建议。
- **决定：**统一基础格式与状态，已有对象变化检查版本；成功活动命令的回执与业务同事务，重复键验证目标和载荷（AD-7）。
- **未采用的备选与理由：**只禁用按钮无法覆盖网络重试和多页面；只靠通知唯一约束不能防止业务再次变更；前后端各写接口假设会把冲突推迟到联调；JSON number 不能无条件精确表示任意 BIGINT ID。
- **代价：**需要回执表及明确的客户端重试约定；重放旧操作结果后还需读取当前状态。状态冲突不能简单显示“成功”。
- **验证计划：**同键重放、同键改载荷、并发跨活动误用同键、旧版本修改、已重报后重放旧审核命令；均不出现重复状态变化或隐私泄露。
- **关联：**FR-14、FR-17、FR-21；NFR-01、NFR-04；具体端点在故事开始前形成一份共享契约。

## ADR-008 迁移管理、同源打包和真实 MySQL 验证

- **背景与状态：**要求正常重启持久化、另一成员能从干净检出复现；技术建议。
- **决定：**Flyway 管理结构，业务保存在 MySQL；开发前后端分进程、交付静态产物随 Boot 打包；一致性验收使用真实 MySQL（AD-8）。
- **未采用的备选与理由：**启动导入并覆盖演示数据会破坏持久性；各自手工改表无法可靠复现；H2 或纯 Mock 无法证明 InnoDB 锁与隔离行为；独立前端托管和多个域名会增加部署与认证配置，本版没有必要。
- **代价：**开发/验证需准备数据库；交付流水线需先构建前端。安装、镜像和 CI 供应仍要实际验证，当前没有运行证明。
- **验证计划：**干净数据库迁移、已有数据库增量迁移、正常重启前后逐项比较业务状态；由另一成员按 README 完成启动和测试。
- **关联：**NFR-01 至 NFR-04；[本次官方脚手架及版本核查](version-research.md)。
